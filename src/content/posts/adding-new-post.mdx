## 创建博客文章

要写新的博客文章，请在 `src/content/posts/` 目录中创建一个 markdown（或 MDX）文件。

你可以将文章组织到子目录中，使内容更易于管理。子目录名称会成为文章 URL 的一部分。例如，`src/content/posts/2025/example-post.md` 将可在 `/posts/2025/example-post` 访问。

如果你只想用子目录组织而不影响 URL，请在文件夹名称前加下划线（`_`）。

```bash
# 示例：文章文件路径及其 URL
src/content/posts/very-first-post.md          -> mysite.com/posts/very-first-post
src/content/posts/2025/example-post.md        -> mysite.com/posts/2025/example-post
src/content/posts/_2026/another-post.md       -> mysite.com/posts/another-post
src/content/posts/docs/_legacy/how-to.md      -> mysite.com/posts/docs/how-to
src/content/posts/Example Dir/Dummy Post.md   -> mysite.com/posts/example-dir/dummy-post
```

> [!TIP]
> 以 `_` 为前缀的文件和目录会被排除在路由之外。可用于草稿、共享资源或仅限内部使用的内容。

## Frontmatter

Frontmatter 是存储博客文章元数据的主要位置。它位于文件顶部，采用 YAML 格式。在 [Astro 文档](https://docs.astro.build/en/guides/markdown-content/)中了解更多关于 frontmatter 及其用法的信息。

以下是每篇文章的 frontmatter 属性列表：

<ResponsiveTable variant="striped-minimal">

| 属性               | 描述                                                                                                                              | 备注                                           |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| **_title_**        | 文章标题。(h1)                                                                                                                    | 必填<sup>\*</sup>                              |
| **_description_**  | 文章描述。用于文章摘要和站点描述。                                                                                                | 必填<sup>\*</sup>                              |
| **_pubDatetime_**  | 发布日期时间，ISO 8601 格式。                                                                                                     | 必填<sup>\*</sup>                              |
| **_modDatetime_**  | 修改日期时间，ISO 8601 格式。（仅在博客文章被修改时添加此属性）                                                                   | 可选                                           |
| **_author_**       | 文章作者。                                                                                                                        | 默认值 = `site.author`                         |
| **_featured_**     | 是否在首页的精选区域显示此文章。                                                                                                  | 默认值 = false                                 |
| **_draft_**        | 将此文章标记为"未发布"。                                                                                                          | 默认值 = false                                 |
| **_tags_**         | 此文章的相关关键词。以 YAML 数组格式编写。                                                                                        | 默认值 = others                                |
| **_ogImage_**      | 文章的 OG 图片。用于社交媒体分享和 SEO。可以是远程 URL 或相对于当前文件夹的图片路径。                                             | 默认值 = `site.ogImage` 或生成的 OG 图片       |
| **_canonicalURL_** | 规范 URL（绝对路径），适用于文章已存在于其他来源的情况。                                                                          | 默认值 = `Astro.site` + `Astro.url.pathname`  |
| **_hideEditPost_** | 隐藏文章标题下的编辑按钮。仅适用于当前文章。                                                                                     | 默认值 = false                                 |
| **_timezone_**     | 为当前文章指定 IANA 格式的时区。仅覆盖此文章的全局 `site.timezone` 配置。                                                         | 默认值 = `site.timezone`                       |

</ResponsiveTable>

> [!TIP]
> 你可以在控制台中运行 `new Date().toISOString()` 来获取 ISO 8601 日期时间。

frontmatter 中只有 `title`、`description` 和 `pubDatetime` 字段是必须指定的。

标题和描述（摘要）对于搜索引擎优化（SEO）非常重要，因此 AstroPaper 鼓励你在所有博客文章中包含这些内容。

如果你在博客文章中省略了 `tags`（换句话说，如果没有指定标签），默认标签 `others` 将用作该文章的标签。你可以在 `src/content.config.ts` 中设置默认标签：

```ts file="src/content.config.ts"
// ...
tags: z.array(z.string()).default(["others"]), // 将 "others" 替换为你想要的默认标签
// ...
```

### Frontmatter 示例

以下是文章的 frontmatter 示例。

```yaml file="src/content/posts/sample-post.md"
---
title: 文章标题
author: 你的名字
pubDatetime: 2022-09-21T05:17:19Z
featured: true
draft: false
tags:
  - some
  - example
  - tags
ogImage: ../../assets/images/example.png # src/assets/images/example.png
# ogImage: "https://example.org/remote-image.png" # 远程 URL
description: 这是示例文章的示例描述。
canonicalURL: https://example.org/my-article-was-already-posted-here
---
```

### VS Code 代码片段（可选）

AstroPaper 包含工作区代码片段，可加速创建新文章：

- **frontmatter**：插入推荐的 frontmatter 块
- **template**：插入基本文章模板（包括 `## Table of contents`）

这些代码片段位于 `.vscode/astro-paper.code-snippets`。如果你使用 VS Code（或 Cursor），打开工作区时应自动可用。

## 提示框

AstroPaper 从 v6.1 开始支持提示框。它们使用简单的 blockquote 语法，由 `rehype-callouts`（Obsidian 主题）驱动。

以下是最常用的类型：

> [!NOTE]
> 读者应该了解的补充信息。

> [!TIP]
> 有用的建议、快捷方式或最佳实践。

> [!WARNING]
> 可能出错或产生意外后果的内容。

> [!DANGER]
> 存在严重的失败、数据丢失或错误行为风险。

> [!INFO]
> 中立的信息背景——比 NOTE 更不紧急。

> [!SUCCESS]
> 确认某事有效或正确。

支持的完整类型列表包括：`NOTE`、`ABSTRACT`、`INFO`、`TODO`、`TIP`、`SUCCESS`、`QUESTION`、`WARNING`、`FAILURE`、`DANGER`、`BUG`、`EXAMPLE`、`QUOTE`——每种类型都有自己的图标和颜色。许多类型还接受别名（例如 `TIP` 的 `HINT` 和 `IMPORTANT`，`WARNING` 的 `CAUTION`）。完整参考请查看 [rehype-callouts 文档](https://github.com/lin-stephanie/rehype-callouts)。

### 可折叠提示框

在类型后添加 `-` 使提示框默认折叠，或添加 `+` 使其展开但可折叠：

> [!WARNING]- 继续前请阅读
> 此内容在读者展开前隐藏。适用于会中断阅读流程的长篇注意事项。

> [!TIP]+ 专业提示（默认展开）
> 默认打开但可折叠。非常适合仍希望首次加载时可见的可选详情。

### 自定义标题

在类型后添加文本，将默认类型标签替换为你喜欢的任何标题：

> [!NOTE] 你知道吗？
> 类型后的文本成为提示框的标题。省略则自动使用类型名称。

### 语法摘要

```md
> [!NOTE]
> 补充信息。

> [!WARNING]- 默认折叠
> 展开前隐藏。

> [!TIP]+ 展开但可折叠
> 默认打开。

> [!DANGER] 自定义标题
> 替换默认标题。
```

## 添加目录

默认情况下，文章不包含任何目录。要添加目录，请编写 `Table of contents` 作为 h2 标题（Markdown 中为 `##`），并将其放置在你希望显示的位置：

```md
---
# frontmatter
---

这里是创建 AstroPaper 博客新文章的一些建议、技巧和窍门。

<!-- [!code ++] -->
## Table of contents

<!-- 文章其余部分 -->
```

## 标题

关于标题有一点需要注意。AstroPaper 博客文章使用 `title`（来自 frontmatter）作为文章的主标题。因此，文章中的其余标题应使用 `h2` ~ `h6`。

此规则不是强制性的，但出于视觉、无障碍和 SEO 目的强烈推荐遵循。

## 语法高亮

AstroPaper 使用 [Shiki](https://shiki.style/) 作为默认语法高亮器，配合 [@shikijs/transformers](https://shiki.style/packages/transformers) 增强围栏代码块。如果你不想使用 transformers，可以移除它们：

```bash
pnpm remove @shikijs/transformers
```

```ts file="astro.config.ts"
// ...
// [!code --:5]
import {
  transformerNotationDiff,
  transformerNotationHighlight,
  transformerNotationWordHighlight,
} from "@shikijs/transformers";

export default defineConfig({
  // ...
  markdown: {
    remarkPlugins: [remarkToc, [remarkCollapse, { test: "Table of contents" }]],
    shikiConfig: {
      themes: { light: "min-light", dark: "night-owl" },
      defaultColor: false,
      wrap: false,
      transformers: [
        transformerFileName(),
        // [!code --:3]
        transformerNotationHighlight(),
        transformerNotationWordHighlight(),
        transformerNotationDiff({ matchAlgorithm: "v3" }),
      ],
    },
  },
  // ...
});
```

## 存储博客内容的图片

以下是两种存储图片并在 markdown 文件中使用它们的方法。

> [!IMPORTANT]
> 如果你需要在 markdown 中设置优化图片的样式，应[使用 MDX](https://docs.astro.build/en/guides/images/#images-in-mdx-files)。

### 在 `src/assets/` 目录中（推荐）

你可以将图片存储在 `src/assets/` 目录中。这些图片将通过 Astro 的 [Image Service API](https://docs.astro.build/en/reference/image-service-reference/) 自动优化。

你可以使用相对路径或别名路径（`@/assets/`）来引用这些图片。

示例：假设你想显示路径为 `src/assets/images/example.jpg` 的 `example.jpg`。

```md
![something](@/assets/images/example.jpg)

<!-- 或者 -->

![something](../../assets/images/example.jpg)

<!-- 在 markdown 中使用 img 标签或 Image 组件不起作用 ❌ -->
<img src="@/assets/images/example.jpg" alt="something">
<!-- ^^ 这是错误的 -->
```

> [!TIP]
> 技术上，你可以将图片存储在 `src` 下的任何目录中。`src/assets` 只是一个建议。

### 在 `public/` 目录中

你可以将图片存储在 `public/` 目录中。请注意，存储在 `public/` 中的图片不会被 Astro 处理，这意味着它们不会被优化，你需要自己处理图片优化。

对于这些图片，使用绝对路径。可以使用 [markdown 图片语法](https://www.markdownguide.org/basic-syntax/#images-1) 或 HTML `img` 标签来显示。

示例：假设 `example.jpg` 位于 `public/assets/images/example.jpg`。

```md
![something](/assets/images/example.jpg)

<!-- 或者 -->

<img src="/assets/images/example.jpg" alt="something">
```

## 额外内容

### 图片压缩

> [!WARNING]
> 将图片放入博客文章（尤其是 `public/` 目录中的图片）时，请先压缩它们。未优化的图片会严重影响页面性能。

推荐的图片压缩网站：

- [TinyPng](https://tinypng.com/)
- [TinyJPG](https://tinyjpg.com/)

### OG 图片

如果文章未指定 OG 图片，将使用默认 OG 图片。虽然不是必须的，但建议在 frontmatter 中指定与文章相关的 OG 图片。OG 图片的推荐尺寸为 **_1200 X 640_** 像素。

> [!TIP]
> 从 AstroPaper v1.4.0 开始，如果未指定 OG 图片，会自动生成。查看[公告](https://astro-paper.pages.dev/posts/dynamic-og-image-generation-in-astropaper-blog-posts/)了解详情。
